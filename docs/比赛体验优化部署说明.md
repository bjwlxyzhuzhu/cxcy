# 比赛体验优化部署说明

## 变更范围

- `/learn/cases` 随源码提供6个2024获奖项目，附高校简介、教育部获奖通知和站外视频；保留原数据库案例区。
- `/learn/templates` 随源码提供BP、5分钟路演、专利交底、合作合同4套原创教学模板，复用原Word/WPS导出工具（HTML兼容.doc）。不冒充官方法律表格或获奖团队原文。
- `/guide` 使用手册、下载入口；`pnpm guide:generate` 从共用手册源生成 `docs/用户使用手册.md` 并检查路由存在。
- 默认阅读模式提高亮度与常用字号；左下角“恢复原星空”关闭覆盖样式，原引擎未改。设置保存在浏览器。
- 成长星图显示学习步骤、具名里程碑和评分表，按赛道、项目标识、维度及满分分组，单次不推断进步，未评分不补0。最近500条里程碑；全部问答仍在我的测试记录。
- 专家/答辩页面新增完整报告生成入口，调用原有AI提供方，自动保存全文并支持导出；答辩准备稿与实际评分分开。
- 登录每天30积分、反思每天10积分（北京时间），同用户同日同奖励唯一；采用余额行锁避免奖励与扣费互相覆盖。反思不公开，不新增论坛。
- 完整报告每份5积分，个人API Key不扣平台积分。服务端预扣、请求幂等、失败退还。进程中断留下的预扣款超过10分钟后，在下次访问积分中心或生成接口时退还。

## 上线

源码推送与生产部署是不同步骤。本仓库main推送会触发现有Docker镜像工作流，不会自动证明服务器已拉取新镜像。

1. 备份现有PostgreSQL数据，并记录当前运行镜像摘要，作为回滚版本。
2. 等待GitHub的测试与镜像工作流完成，在原部署环境拉取本次提交对应的镜像。
3. 使用原服务器环境变量启动。根目录Compose的迁移服务会运行 `scripts/migrate.mjs`，需成功应用 `0016_competition_experience.sql`；若单独启动容器或使用自定义Portainer Stack，须先用同一数据库环境执行 `node scripts/migrate.mjs`，容器启动脚本本身不自动迁移。这次迁移只新增表及兼容列，不重置历史余额或学生数据。
4. 使用测试账号核验：登录奖励当天一次，积分中心反思一次，报告生成与历史回放，模板下载，界面恢复。原AI环境变量不变，未配置AI时明确报错并退分。

若使用仓库根目录Compose，原部署环境中执行：

```sh
docker compose -f docker-compose.postgres.yml --env-file .env.local pull
docker compose -f docker-compose.postgres.yml --env-file .env.local up -d
docker compose -f docker-compose.postgres.yml --env-file .env.local logs --tail=80 migrate cxcy
```

不要创建新的空数据库代替现有学生数据库，也不要把 `.env.local` 或密钥提交GitHub。

## 回滚

界面恢复：点击“恢复原星空”，即时恢复原配色与字号。代码回滚：部署先前记录的镜像摘要。新增表可保留，不执行DROP，不删除奖励、报告或学生历史数据。若有pending报告，先记录其请求编号并在新版本积分中心核对/退分后回滚，避免遗留预扣款。

## 资料维护

获奖事实来源：教育部2024获奖通知与上海交通大学2024-10-15总决赛报道；项目补充来源为交大与中国地质大学（北京）官网。各链接在 `web/lib/resource-library.ts`。视频为第三方分享/合集，仅链接，不托管。专利官方入口为国家知识产权局，合同示范文本为市场监管总局。维护者应定期复核站外链接。

## 验证

```sh
cd web
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
pnpm test:integration
pnpm guide:generate
pnpm build
```

HTTP集成测试使用本地AI替身，不连接生产数据或付费模型。默认PGlite供快速回归；完整并发验收必须将 `TEST_DATABASE_URL` 指向空的独立PostgreSQL测试库（库名必须以 `cxcy_test` 开头），CI已配置PostgreSQL 16服务。每次测试使用新库，测试不会清空已有数据库。PGlite socket多连接扩展协议存在34000 portal错误，因此其模式只验证报告顺序幂等，不代替真实数据库并发测试。

真实模型输出质量仍取决于服务器配置。Windows本地无符号链接权限时仅验证构建可设置 `NEXT_DISABLE_STANDALONE=1`，Linux/Docker保留standalone默认输出。
