# 智能体平台部署说明（SQLite 版，不依赖 Supabase）

> 2026-11-16 起不再使用 Supabase。数据库是一个 SQLite 文件（Node 内置 `node:sqlite`），账号与登录会话由平台自己管理。
> 代码里不写死任何域名，所有地址与密钥都在 `.env.local` 里配置。

## 一、本机开发（Windows）

要求：Node 24 及以上（本机已验证 Node 26）、pnpm。

```bash
pnpm install
cp .env.example .env.local      # 填 SESSION_SECRET 与 CHAT_API_KEY
node --env-file-if-exists=.env.local scripts/create-user.mjs <教师账号> <密码> teacher
pnpm dev                        # http://localhost:3000
```

- 数据库文件默认在 `data/app.db`，第一次启动或执行脚本时自动建表（`db/migrations/` 下按文件名顺序执行）。
- `SESSION_SECRET` 生成方法：`node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"`。
- 提交前检查：`npx tsc --noEmit` 与 `pnpm build` 都要通过。自测脚本：
  - 数据层：`node scripts/test-db.mts`
  - 证据判定正反例：`node --test scripts/test-cites-evidence.mts`
  - 项目本体动作引擎：`node --test scripts/test-ontology.mts`
  - AI 自动建本体（抽取与防编造）：`node --test scripts/test-extract.mts`
  - 口径与术语表：`node --test scripts/test-glossary.mts`
  - 产品线 8 步进度判定：`node --test scripts/test-progress.mts`
  - 产品线半自动化（起草校验、路演页与档案）：`node --test scripts/test-generate.mts`
  - 统一 AI 上下文层（只含人认过的内容、出处校验）：`node --test scripts/test-context.mts`
  - 智能引导师（五力只计已认证记录、现实验证预审、干预卡权限与去重）：`node --test scripts/test-guide.mts`
  - 班级与教师关联（教师只看本班项目）：`node --test scripts/test-classes.mts`
  - 虚实对局整局联调（本机模拟模型，不出本机）：先 `node scripts/mock-llm.mjs`，再 `E2E_TEACHER_PASSWORD=… E2E_STUDENT_PASSWORD=… node scripts/test-arena-e2e.mjs`
- Windows 下 `pnpm build` 默认不产出 standalone（避免 pnpm 符号链接导致下次构建报 EPERM）；Docker 镜像在 Linux 里构建，会正常产出。

## 二、服务器部署（Docker）

要求：Linux 服务器、Docker 与 Docker Compose。

1. 上传本目录到服务器（不要带 `data/`、`.env.local`、`node_modules`）。
2. `cp .env.example .env.local`，填写：
   - `SESSION_SECRET`：服务器上重新生成一份，不要沿用本机的；
   - `CHAT_BASE_URL / CHAT_API_KEY / CHAT_MODEL`；
   - 经 HTTPS 反向代理访问时 `SESSION_COOKIE_SECURE` 可留空（自动判断）或设为 `1`；纯 http 内网访问设为 `0`。
3. 启动：

```bash
docker compose up -d --build
```

4. 创建首个教师账号：

```bash
docker compose exec web node scripts/create-user.mjs <教师账号> <密码> teacher
```

5. 先用 `http://服务器IP:3000` 检查，再用 Nginx 或 Caddy 配置域名与 HTTPS。反向代理要转发 `X-Forwarded-Proto`、`X-Forwarded-For` 两个请求头（会话 cookie 的 Secure 判断和登录限流要用）。

## 三、账号与名册

- **教师/管理员**：只能用命令行 `scripts/create-user.mjs` 创建，或由已有管理员在后台把某个账号改为教师。
- **学生**：管理员在后台“名册导入”上传 CSV（学号、姓名、班级、学院、专业），账号即学号，默认每人随机临时密码；导入后立即下载凭据表，逐人发放。
  命令行等价做法：`node --env-file-if-exists=.env.local scripts/import120.mjs <名册.csv> [积分]`，凭据表写到 `data/` 下。
- 改密码（本人改或管理员重置）后，该账号在其他设备上的登录会立即失效。
- 同一账号加同一来源 IP 连续输错 5 次密码，锁定 5 分钟。

## 四、备份与迁移服务器

- 数据全部在 `data/app.db`（运行中还会有 `app.db-wal`、`app.db-shm` 两个伴随文件）。
- 在线备份（不停服务）：

```bash
docker compose exec web node -e "const {DatabaseSync}=require('node:sqlite');new DatabaseSync('/app/data/app.db').exec(\"vacuum into '/app/data/backup.db'\")"
```

- 迁移到新服务器：停服务 → 拷走整个 `data/` 目录 → 新服务器按第二节部署后放回 `data/` → 启动。
- 改表结构一律新建 `db/migrations/0002_*.sql` 这类文件，不要改已执行过的迁移文件。

## 五、权限模型（去掉 Supabase RLS 之后）

数据库不再有行级安全策略，所有读写都经服务端接口，权限在接口里判断：

- 未登录：只能访问登录接口和首页公开统计（统计里不含任何姓名）。
- 学生：只能读写自己的档案、密钥、项目、证据、干预卡；对局里只能操作本队的假设、以本队身份交锋。
- 教师/管理员：开局与轮次控制、确认现实验证、大屏数据、管理后台、研究导出。

新增接口时必须先调用 `getUser()` / `requireAdmin()`，并在查询里显式加上 `user_id = 当前用户` 或本队条件。
