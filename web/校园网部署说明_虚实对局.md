# 校园网部署说明 · 虚实对局版（2026-11）

目标：把「双创AI星际」整体部署到学校提供的校园网云主机上，数据库自建（不出校、不出境），对话模型统一用 DeepSeek V4.1。

## 一、本次新增了什么

| 模块 | 地址 | 谁用 |
|---|---|---|
| 分身工坊 | `/apply/twin` | 学生注入调研生成数字分身；教师一键注入评委/投资人/导师/伦理/商业/合规/钛产业角色 |
| 虚实对局（学生端） | `/apply/arena` | 学生凭大屏对局码入队，与分身对抗、与导师协作、维护假设看板 |
| 教师大屏 | `/arena/screen` | 教师开局、控轮次、确认现实验证；投屏显示排行、五维雷达、虚实闭环漏斗、实时动态 |

数据库新增 `supabase/migrations/0012_arena.sql`（personas、arena_matches、arena_teams、arena_members、hypotheses、arena_events 六张表 + 匿名研究视图）。对局过程同时写入 0011 的 challenge_sessions / dialogue_turns / plan_versions，管理后台「研究数据导出」新增 arena_events 工作表。

**顺带修复**：原 `_ALL.sql` 中 0011 段落的中文注释已乱码，执行会报语法错误、对抗对话表建不出来。已按 0001—0012 原文件重新合并。

## 二、云主机要求

- Ubuntu 22.04/24.04，建议 4 核 8G（自建 Supabase + 网站同机）；最低 2 核 4G。
- 校园网内访问即可，无需公网与 ICP 备案；需能访问 `https://api.deepseek.com`（出站 443）。
- 安全组只放行 22、80（或 443）；Supabase 的 5432/8000 不对外。

## 三、部署步骤

1. **自建 Supabase**：按 `../部署迁移手册_国内服务器.md` 第 1—2 节执行。
2. **建库**：Studio → SQL Editor，粘贴执行 `supabase/migrations/_ALL.sql`（已含 0012，全部幂等）。已有库只需补执行 `0011_adversarial_dialogue.sql`（若之前没成功）和 `0012_arena.sql`。
3. **环境变量**：复制 `.env.example` 为 `.env.local`，至少填：
   ```
   NEXT_PUBLIC_SUPABASE_URL=http://云主机内网IP:8000
   NEXT_PUBLIC_SUPABASE_ANON_KEY=...
   SUPABASE_SERVICE_ROLE_KEY=...
   CHAT_BASE_URL=https://api.deepseek.com
   CHAT_API_KEY=你的 DeepSeek Key
   CHAT_MODEL=deepseek-flash
   ```
   `deepseek-flash` 是 DeepSeek V4.1 Flash 的官方模型名。APIMart 可留空：配图和知识库向量检索会自动降级，不影响对局。
4. **启动**：`docker compose --env-file .env.local up -d --build`，浏览器访问 `http://云主机内网IP:3000`。
5. **账号**：管理后台「名单导入」导入 30 名学生；把你自己的账号在 profiles 表里设为 `role = teacher`。
6. **研究同意**：参与录课并同意科研使用的学生，在 profiles 里设 `research_consent = true`、`research_pid = T01-S01` 这类编号；未同意者照常上课，数据不进入导出。

## 四、录课前演练清单

- [ ] 教师账号进 `/apply/twin`，点「一键注入默认角色」，按需修改各角色的关注重点。
- [ ] 每队至少 1 名学生把真实访谈注入一个分身（全班可见），队伍编号填 T1—T6。
- [ ] `/arena/screen` 开局：6 队、3 轮、每轮 12 分钟；投屏显示对局码。
- [ ] 学生手机/电脑打开 `/apply/arena`，选队、输入对局码入队，填写本队"AI 原生微企业"一句话。
- [ ] 5—10 人试玩一局：确认交锋、加入假设、证伪、提交验证、教师确认 +5、大屏刷新都正常。
- [ ] 30 人并发前检查 DeepSeek 账户余额与并发；平台积分默认每次交锋扣 1 分，录课前给学生账号补足积分。

## 五、计分规则（记在证据上，不按聊天轮数）

- 回应质询时拿出具体证据（数据 / 访谈原话 / 实测）：+1（每队每轮最多 8 次）
- 提出一条可检验假设：+1（每队每轮前 5 条）
- 证伪自己的假设并写出修正：+3
- 回到现实验证并经教师确认：+5
- 本队做的分身让别队证伪了假设：+1（奖励扎实调研）

分身只依据注入的调研说话；资料里没有的会直说"去现实中问问"，学生可一键把它加入待验证假设——这就是虚实闭环。


## 2026-11-16 更新：对战画面版

本次把学生端、分身工坊、教师大屏改成了对战画面（人物头像、头顶对话、能量条、回合横幅），并增加了队内席位。

**升级步骤（已部署过旧版的环境）**

1. 在 Supabase SQL 编辑器执行 `supabase/migrations/0013_arena_seats.sql`（只加一列一个索引，可重复执行）。全新环境直接执行 `_ALL.sql` 即可，已包含 0013。
2. 确认 `public/avatars/` 下有 17 张头像（12 个角色 + s1–s5 五个学生席位），随镜像一起打包。
3. 重新构建并启动：`docker compose build && docker compose up -d`。

**页面与用法**

| 页面 | 地址 | 用途 |
|---|---|---|
| 学生对战 | `/apply/arena` | 入队时选战队和席位（队长/调研/产品/财务/路演）；选对手后出招，带证据才命中 |
| 分身工坊 | `/apply/twin` | 创建角色；分身上台逐项复述角色卡，学生确认或修改 |
| 教师大屏 | `/arena/screen` | 三个模式：对战看板（各队成员席位与个人贡献）、焦点对战（把一支队伍的交锋投到全班）、四层闭环（实时统计） |

**画面上的数字是怎么来的**

- 假设护盾：每次发言没带证据 -16，分身回答“资料里没有”再 -12；降到底不算输，只提示去现实验证。
- 质疑值：每次带证据的发言 -18。
- 这两条只是画面反馈，不计入成绩；成绩只来自 `arena_events` 的证据值。
- 四层闭环页的全部数字来自数据库真实记录，没有任何预置数据。

**更换头像**：直接替换 `public/avatars/` 下同名 jpg（建议 512×512 以上的单人方图），无需改代码。大屏焦点对战的头像显示为 300 像素，当前图片是从合图裁出的 360 像素小图，投到大屏会略糊。

**大屏只显示席位和虚拟头像，不显示学生姓名**，可直接用于匿名版录屏。
