# 报告生成故障修复

## 问题与修复

2026年9月27日公网走查中，专家报告与模拟答辩准备稿返回502并退分。对照请求显示，平台模型为 `deepseek-flash`：短问答正常，4000 token上限的长文本请求返回空正文。旧报告接口使用同样的4000上限，且未指定思考模式。

DeepSeek当前文档说明Flash默认开启思考，思考内容与最终正文是不同字段。小输出预算可能在正文产生前耗尽。由于没有生产日志，不能排除其他部署问题；本次修复针对该已复现的空正文路径，不声称取得了上游原始推理内容。

- 专家报告与答辩准备稿对已知DeepSeek Flash/V4模型发送 `thinking: {type: "disabled"}`，正文上限改为8192；其他兼容模型不发送专用字段。
- 使用Node SDK直接序列化扩展参数，不使用Python SDK的`extra_body`包装。
- 继续拒绝空正文、截断正文和内容过滤结果，不拿思考过程充当报告。
- 给出安全错误码，区分输出上限、空正文、认证、限流、超时和数据库保存失败。保留预扣、失败退还和请求幂等机制。
- 普通问答的空正文不再作为成功结果保存和收费。

官方依据：https://api-docs.deepseek.com/guides/thinking_mode/

## 更新运行环境

本次不改数据库结构，不清空原有记录。GitHub推送与Docker镜像构建不会自动证明生产容器已经更新。使用Portainer时重新部署现有Stack并拉取新镜像；命令行部署沿用根目录Compose文件，拉取新镜像后重建应用服务。若镜像固定为旧sha标签，需改为本次提交对应的sha标签或新latest。不要删除数据库卷。

部署后打开专家打磨，点击“新建请求 / 修改材料”，重新填写材料生成；旧的失败请求已退分，不能复用旧编号当作新生成。若仍报错，界面错误码和请求编号用于定位，不应上传API密钥。
