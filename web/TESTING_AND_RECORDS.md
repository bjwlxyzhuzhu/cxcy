# 课堂测试与记录功能

本次交付是源代码。导出文件由网站运行时生成，原始学生测试材料不在仓库中。

## 学生使用

1. 使用原账号登录，在各模块正常对话。发送的原话先保存，AI回复随后保存到同一记录。
2. 从“我的测试记录”查看历史、下载或继续对话；模块内也会恢复最近的同名练习。
3. “新建练习”创建新的记录，不删除旧记录。退出登录只移除登录凭据，不删除学习记录。
4. 驾驶舱从“历史记录”查看完整过程，可将历史的最后输出恢复到草案继续修改。

原版只存在网页内存且已经消失的对话无法恢复。旧版已保存的项目、成长证据及实验事件保留，不伪造缺失原话。未提交的普通对话输入不等于已保存记录；课堂实验输入有单独的本地和云端草稿。

## 新版课堂实验

教师在后台“课堂实验”选择题材、命名课堂、创建实验并点击“开放实验”，再分享实验码和 `/experiment` 地址。学生点击“提交并进入…”后，系统自动切换步骤，在驾驶舱、专家打磨和模拟答辩的课堂实验模式中继续，无需手动寻找普通模块。课堂建议约40—50分钟，但系统不按时钟强制清空或切换。

提供实验一（AI学习与就业陪伴）、实验二（校园闲置物品循环服务）、实验三（家乡农产品预订配送），支持自定义名称、案例背景和通俗说明。每场课堂在 `experiment_runs.scenario` 保存完整题材快照，创建后不修改。不同题材分别开设课堂，学生可退出后用新实验码参加；原记录仍保留，登录账号可以从“继续我参加过的实验”恢复。不将不同题材的前后测混合计算提升。

入口有教师与学生操作指导，每个步骤说明目标、操作顺序和完成条件。前测、导读、V0、V1、最后一题答辩、后测与反馈均支持一次提交保存并前进；专家打磨和答辩自动呈现下一题。提交与阶段更新在同一数据库事务中，网络重试不会重复记录或重复前进。

驾驶舱 `/apply/cockpit?experiment=1` → 专家打磨 `/apply/expert?experiment=1` → 答辩 `/apply/defense?experiment=1` 共用实验工作台和同一个参与编号。V0/V1及前序回答直接从数据库带入，并提供给AI求助作为背景；课堂回答继续写入实验事件，后台和导出实时读取同一份数据。此模式保留课堂题数、分组和独立前后测规则，与普通自由练习界面区分。地址过期或误进其他模块时，自动定位当前步骤。完成答辩自动回到 `/experiment` 做后测。

浏览器实际走查覆盖：实验三创建/开放、学生加入、前测、导读、驾驶舱输入并刷新恢复、V0传入专家页、5轮含求助/跳过、V1传入答辩、3题后返回后测、反馈和完成页。使用隔离数据库和本地AI替身，不使用真实学生账号或生产数据。

流程：前测 → 项目导读 → 初步方案V0 → 专家打磨5轮及修改版V1 → 模拟答辩3题 → 后测 → 体验反馈 → 查看与导出。

- A组沿用原代码的综合专家，B组沿用五位专家。按加入顺序交替分配，不是随机分组，也不据此宣称因果效果。
- 两组使用相同核心问题，每轮只显示一个问题。专家身份由服务端确定，解释与回答框架可按需求助。
- 本版为初学者流程，不继续执行旧版的多次强制追问。问题来自固定协议题库；AI负责解释和反馈，不能在前后测提供答案。
- 回答、跳过、求助和AI内容分别记录。完成问答步骤不代表回答质量合格，能力评分默认NULL，不将未完成计为0分。
- 前后测共同记录判断、两个关键条件、风险和1—5分把握程度。后测的观点变化及体验反馈独立保存，不计算混合总分。
- 登录后加入会关联账号，同账号同实验再次加入恢复原参与者；匿名参加需保存恢复码。恢复码是个人访问凭据，不进入研究导出。
- 旧实验使用 `legacy-v1` 标识，仍可查看和导出。请新建实验使用 `guided-v2`，不会覆盖旧分组和事件。

## 管理员查看

管理员后台的“学生管理”“课堂实验”“研究数据导出”均提供明确的“导出全体教学测试数据”入口。它汇总全部账号的普通练习、课堂实验、历史项目/方案/答辩与督导卡，不受列表分页或个人筛选限制。入口仅账号角色为 admin 时显示，接口 `/api/admin/records/export` 再次核验角色；未登录、学生、普通教师均返回403。学生端仅保留自己的记录导出。教学导出含身份和未同意科研使用的记录，科研用途仍应走单独的同意筛选出口。

“学生管理”显示每个账号的对话数量、实验次数和在线状态，点击记录链接进入该学生的记录列表。“课堂实验”提供实验选择、进度汇总、前后测缺项、个人事件详情及导出。匿名参与者按固定编号显示，无法推断真实账号。

在线状态的定义：页面可见时每45秒发送一次心跳，服务端最近2分钟有登录或心跳即显示“近期在线”；后台每30秒刷新。仍有有效登录会话但超过2分钟未活动，显示“已登录，暂未活动”。退出全部会话后显示“已离线”。多个设备按任一有效会话判断，最后活动时间保留。此状态不代表学生持续注意或正在回答。

## 导出与数据结构

### 分组、前后测和时间

课堂实验导出（学生个人、教师课堂和研究出口）提供中文分析字段。Excel保留“完整记录”，另有“分组汇总、参与者与缺项、前测、后测、前后测配对、阶段用时、过程记录”工作表。Word/PDF/RTF/Markdown按同名章节组织；CSV有“数据表、实验编号、固定编号、分组、测量阶段”等列；JSON保留分表结构。普通练习明确标注无实验分组/前后测。教师可按A/B组筛选导出。配对只使用同场实验固定编号，不混合不同题材与量表，也不生成无依据的能力提升总分。

所有可用时间显示北京时间（UTC+8），并保留原始UTC字段：加入、可开始、前后测提交、逐条问答、完成及阶段起止。可开始时间取加入与老师开放时间中较晚者；阶段起止使用服务器保存的进入/离开事件，经过秒数包含离线与停留，不等于有效学习时长。没有时间、没有结束事件或时间倒序时不计算时长；历史缺项保留NA。题目生成至提交间隔不是纯思考时间。

### 历史综合督导与自动提示

“干预督导”默认显示每位学生一张个人历史综合卡，按账号回查成长证据、已存项目、方案版本、历史答辩场次/对话、普通练习及课堂实验。卡片包含各来源计数和有限的原文摘录，不冒充逐条语义质量评价。无记录时显示待核对，不推断没有学习。匿名记录按参与编号，不按姓名/IP猜测并入账号。外部问卷、原来只在浏览器内存且已丢失的数据不会凭空恢复。

普通练习回复保存、课堂提交/求助和关闭时同步规则卡；后台打开或每30秒刷新时检查并补查历史。每次最多100份课堂/普通练习增量记录，页面提示剩余批次；个人综合卡按学生账号回查。来源+规则唯一约束保证同一实验不重复发卡，新的实验分别处理，教师备注与学生回应保留，撤回不会自动重发。旧卡保留查看，新提示使用已保存事实，不依赖付费模型，不作能力诊断。学生前后测仍在进行时不会被标成缺测，关闭课堂后才检查最终缺项。

新增 `0015_supervision_sources.sql`，启动容器会随现有迁移机制执行；更新运行代码后首次进入督导页即可回查真实数据库。提交源码本身不等于已给生产学生生成卡片。

学生记录、各实验模块、个人完整实验、管理员课堂记录和研究数据都支持 DOCX、RTF、XLSX、PDF、CSV、JSON、Markdown。DOCX、RTF为真正对应格式；没有将HTML改名冒充DOCX。原有旧版 `.doc` 内容按钮保留兼容，新测试记录使用统一导出入口。

- `learning_sessions` 绑定账号、模块与练习；`learning_records` 保存完整原话、AI回复、附件文本及模型来源。图片仅记录名称，不宣称保存图片原件。
- `experiment_participants.participant_code` 是稳定编号；`experiment_events` 保存阶段、问题、角色、轮次、回答状态、请求编号及时间；`experiment_drafts` 保存未提交草稿。
- Excel/CSV 将嵌套字段展开，超过30000字符的文本按 `record` / `part` 分段，避免Excel单元格上限造成截断。JSON保留原结构。
- 研究导出只纳入同意研究的账号/实验参与者，编号不随排序变化。学生自行在自由文本输入的身份信息仍需研究者发布前复核。
- 管理教学导出包含账号，研究导出移除结构化姓名、学号和恢复码。历史问卷不按序号、IP或文件数量自动配对。

## 更新运行环境

沿用原项目 PostgreSQL、Next.js 和 GitHub Actions Docker流程。无新增外部服务账号。

```bash
cd web
pnpm install --frozen-lockfile
pnpm migrate
pnpm build
pnpm start
```

新增迁移 `0012_learning_records.sql`、`0013_presence.sql` 与 `0014_experiment_scenarios.sql`，为追加表/字段，不删除旧数据。历史课堂保留原AI案例。容器原有启动脚本会执行迁移。非容器启动需先设置 `DATABASE_URL` 并执行 `pnpm migrate`。回退旧代码时可以保留新表；不要删除记录表。部署前按原数据库备份流程操作。

Docker运行层增加 `font-noto-cjk`。非Docker Linux需要安装中文字体或设置 `EXPORT_PDF_FONT`；TTC集合字体可以用 `EXPORT_PDF_FONT_FAMILY` 指定字体名称。Windows默认使用系统宋体。缺少中文字体时PDF接口明确报错，不生成乱码文件。

## 验证

数据库连接池通过进程级缓存供各API路由及热更新复用，每进程最多10条连接。HTTP集成测试在跨模块操作后、全体七种格式导出后检查实际连接数不超过10，防止多份路由包重复建立连接池而耗尽数据库连接。测试数据库的64条连接上限不放宽，连接异常仍会使测试失败。

Windows未开启符号链接权限时，可在PowerShell设置 `$env:NEXT_DISABLE_STANDALONE='1'` 后构建并运行本地生产测试。默认配置仍生成Docker所需的standalone产物，GitHub/Linux构建不要设置此变量。

```bash
pnpm typecheck
pnpm test
pnpm test:integration
pnpm build
```

`pnpm test` 检查协议门槛、数值范围、历史迁移及七种导出格式，DOCX/PDF/XLSX会回读内容。PDF测试需要中文字体。

`pnpm test:integration` 启动隔离PGlite数据库和本地AI替身，调用真实Next.js HTTP接口，验证登录、退出恢复、跨账号隔离、幂等、草稿、阶段限制、8轮问答、前后测配对、后台记录、在线状态及导出。仅占用本机3318、3319、55439端口，不连接生产数据库，不调用付费AI。设置 `TEST_PRODUCTION=1` 可在 `pnpm build` 后验证生产构建。此测试不能代替真实模型的教学效果评价及真实多连接PostgreSQL负载测试。

主要源码：`lib/experiment-protocol.ts`、`lib/learning-records.ts`、`lib/report-export.ts`；`app/api/experiment`、`app/api/records`、`app/api/admin/records`、`app/api/presence`；`components/admin/ExperimentAdmin.tsx`、`components/admin/StudentManager.tsx`。
